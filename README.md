# 深维 · 公众号组件库

一句话版本：把你的网页原样送进微信公众号编辑器，然后让排版这件事少占你半小时。

当前版本 4.8.1。Chrome 114 及以上，Manifest V3。数据全在本地，不用登录，也不上传任何东西。

## 为什么要做这个

做公众号的人大概都遇过这种事。在别处排好的一页内容，复制进公众号编辑器就像过了一遍水，颜色浅了，SVG 变黑了，模块之间那点精心调过的间距挤成一团。再手动调一遍，半小时就没了。

这个插件最早就是为了治这个毛病。它不提供三种兼容模式让你挨个试，只有一种行为：把你给的 HTML 按原样送进编辑器，`<style>` 留着，颜色留着，SVG 留着，模块结构也留着。

后来顺手加了几样常用的东西。66 个排版组件，23 个快捷排版动作，3 个能固定的插槽。它们全挤在页面里的同一个浮窗中，不另开窗口，不抢占侧边栏。

## 安装

```bash
git clone https://github.com/Nightando/DeepInsight-wpeditor.git
```

也可以在 GitHub 页面点 Code 下载 ZIP，解压到一个固定位置，后面更新都在这个目录里进行。

然后：

1. 打开 `chrome://extensions`，Edge 用 `edge://extensions`
2. 打开右上角的开发者模式
3. 点「加载已解压的扩展程序」，选中刚才的目录
4. 打开微信公众号编辑页面，点浏览器工具栏里的插件图标

图标点一下展开浮窗，再点一下收起。没有弹窗入口，也没有侧边栏入口，就这一个窗口。

## 怎么用

### 一、把网页原样注入

这是看家本领，值得多说两句。

点浮窗「快捷操作」区的「导入 HTML」。弹窗里可以选一个本地 `.html` 文件，也可以直接拖进去，还能粘贴 HTML 代码。导入后先给一次预览，确认没问题再点「注入编辑器」。

注入走的是逐段插入。样式表先进正文，然后每个顶层节点作为独立片段依次插进去。这么做是因为编辑器在空文档状态下会把一大段 HTML 压平，样式就被剥掉了。逐段插进去，class 定义的颜色和间距才认得出来。

一个建议：导入前先把编辑器正文清空，再导入一次。这是最容易暴露格式丢失的场景，也是最该先试的场景。

### 二、组件库，看一眼再放进去

组件库有 66 个组件，分成文本段落、信息框、数据展示、布局分隔、标签、引用金句、列表序号、问答教程、时间轴、图片媒体、分隔装饰、结尾模块这 12 类。顶部可以搜名字或描述，搜不到会给一个清除筛选的入口。

鼠标停在卡片上约 0.13 秒，旁边会浮出一个小窗，显示这个组件的预设效果。这里看的是默认文案，不是你编辑器里选中的内容，所以它只让你认一眼长相。窗口高度跟着浏览器视口走，矮屏收着点，大屏最高能到 480 像素，长组件也能看完整。

看中了，点一下卡片，组件就插到光标所在的位置。如果正文里正好选中了一段文字，这段文字会被套上组件的样式替换掉原来的样子，适合把已有内容快速换成某种版式。

想改参数就按 Shift 再点卡片，弹窗里每个字段都能调，还有实时的参数预览。

键盘也能用。Tab 走到卡片，回车或空格插入，Shift 加回车调参数，和鼠标操作一一对应。

卡片上那个「快捷」按钮是把组件钉到浮窗上方的自定义插槽里，一共 3 个位。常用的组件钉上去，以后不用翻组件库。

### 三、快捷排版，选中就能改

浮窗最上面是快捷排版，23 个动作，分常用操作、段落格式、标题样式、文字强调、常用插入五组。

选中正文里的文字再点按钮，样式直接套在选中的字上。没选中的话，按钮会插入一段示例内容，方便你先看效果。

这里有个容易忽略的细节：公众号正文在同源 iframe 里，插件会跨帧找到编辑器，选区和样式操作都落在真正的正文文档上。所以不用奇怪为什么主页面的 Selection 读不到东西，那是正常的。

一键美化处理整篇，其余动作以当前选区为准。选中含 `<` 或 `&` 的文字也不会被当成标签解析。

### 四、浮窗本身

浮窗可以按住头部拖动，拖到屏幕边缘会吸附。拖到中间就停在中间，不会一松手弹回去。

位置条上有四个芯片，排版、插槽、操作、组件库，点一下跳到对应分区，滚动时也会高亮当前分区。右边那条细轨是真的滚动轨，能看出整篇内容走到哪了。

窗口拉高拉矮，浮窗高度跟着视口变，不会卡在某个固定值。收起来是一根 32 像素宽的细条，点开就恢复。

## 它不会做的事

这一节可能比功能介绍更值得看。

- 不登录，不上传，不读取你的文章传到别处。组件、插槽和设置都在浏览器本地。
- 不往公众号编辑器的原生菜单里塞按钮。那套菜单没有开放注册自定义项的接口，硬塞进去会被框架重渲染抹掉，还会把样式作用到错误的文档上。
- 不提供兼容模式、保真模式之类的开关。注入就一种行为，省得每次还要猜该选哪个。

## 目录长什么样

```text
.
├── manifest.json           扩展声明与权限
├── background/
│   └── background.js       帧探测与逐段注入
├── content/
│   ├── content.js          唯一浮窗、快捷排版、插槽、选区桥
│   ├── content.css         浮窗布局与视口自适应
│   └── panel.js            组件库面板，HTML 与 CSS 内嵌其中
├── components/
│   └── components.js       66 个组件的定义与渲染
├── shared/
│   └── sanitize.js         脚本剥离与文本转义
├── icons/                  四种尺寸的图标
├── tools/
│   ├── check-extension.mjs 自检脚本
│   ├── selftest.html       浏览器端自测页
│   └── test.html           辅助测试页
└── MAINTENANCE.md          变更记录、回归清单与已知限制
```

注入链是锁定的。从 `panel.js` 的预处理到 `background.js` 的逐段插入，这一路的行为以 2026 年 11 月 8 日的备份版为准。自检脚本会把其中四段函数逐字比对，防止手滑改坏。改 UI 可以，别动注入链。

## 开发者自检

```bash
node tools/check-extension.mjs
```

看到 `[OK] 全部关键检查通过` 才算完。脚本会检查 5 个 JS 文件的语法、66 个组件、浮窗结构、卡片交互、视口自适应算式，以及注入链是否与基准一致。

`tools/selftest.html` 要从项目目录用 `file://` 打开。静态预览服务不映射同目录脚本，会报 403，那是环境限制，不是页面坏了。

想跑真实浏览器回归，项目同级的 `_di_e2e/` 目录里有 Edge headless 脚本，需要 `puppeteer-core`。这部分不属于扩展本体，没有打包进仓库。

## 已知限制

- 真实公众号编辑器里的插入效果需要登录实测。仓库里的自检覆盖页面结构和脚本层，替代不了编辑器里的实际验证。
- 原生菜单无法合并，原因写在 `MAINTENANCE.md`，不要反复重试这条路。
- 悬停预览展示的是组件默认文案，不读取编辑器选区，这是刻意设计的，避免误以为预览就是插入结果。
