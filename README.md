# 深维 · 公众号组件库

> 版本 4.8.1 · Chrome 114 及以上 · Manifest V3 · 数据本地存储

本扩展面向微信公众号内容编辑场景，解决两类高频问题：外部网页内容粘贴到公众号编辑器后样式丢失，以及正文排版需要反复手动调整。扩展以页面内唯一浮窗承载全部功能，不新增弹窗入口，也不占用侧边栏。

## 安装与启用

克隆仓库或下载压缩包，将目录放置在一个固定位置：

```bash
git clone https://github.com/Nightando/DeepInsight-wpeditor.git
```

在浏览器中按以下步骤加载：

1. 打开 `chrome://extensions`，Edge 浏览器使用 `edge://extensions`。
2. 启用页面右上角的「开发者模式」。
3. 点击「加载已解压的扩展程序」，选中项目根目录。
4. 打开微信公众号文章编辑页面，点击浏览器工具栏中的扩展图标。

扩展图标为单一入口。点击一次展开浮窗，再次点击收起。扩展未注册 `default_popup` 与 `side_panel`，因此不存在第二套界面。

后续更新代码后，需在扩展管理页点击重载，并刷新编辑页面。

## 功能详解

### 3.1 HTML 原样注入

这是扩展的核心能力。目标不是把网页内容转换成编辑器兼容格式，而是尽可能保留原始呈现结果，包括 `<style>` 中定义的颜色、间距、布局方式，以及 SVG 的描边与填充。

**导入方式**

点击「快捷操作」区的「导入 HTML」打开弹窗，支持三种输入：

- 点击文件选择区选取本地 `.html` 或 `.htm` 文件
- 将文件直接拖拽到选择区
- 在文本框中粘贴 HTML 源码

弹窗内提供效果预览。预览内容置于独立 Shadow Root 中，仅剥离脚本类标签与事件属性，保留 `link`、`meta`、`style`、`@import` 及完整的结构与样式，因此不会污染弹窗自身的界面样式。

**预处理流程**

导入的 HTML 在插入前经过以下处理：

1. 收集所有 `<style>` 节点，保存为独立片段，并从原位置移除。
2. 识别块级元素与行内元素，将正文拆分为独立区段，避免整块内容被编辑器压平。
3. 移除 `onclick`、`onload`、`onerror` 等事件属性，以及 `javascript:` 协议链接。
4. 为每个顶层节点补充 `display:block` 与 `clear:both` 隔离样式，输出平级的独立片段。

样式表作为首个片段进入正文，其后依次插入各内容片段。class 定义的颜色、弹性布局、模块间距与 SVG 描色因此能够正常生效。

**插入流程与降级链**

插入操作按以下顺序尝试，前一级失败才进入下一级：

1. 后台脚本探测同源 iframe，通过 `scripting.executeScript` 将片段逐段写入编辑器所在帧。
2. 回退到内容脚本的 `insertHTML` 消息通道。
3. 若内容脚本尚未注入，主动注入后重试。
4. 全部失败时将 HTML 复制到剪贴板，由用户手动粘贴。

逐段插入是必要设计。编辑器为空时，光标停留在首行的 `<p><br></p>`，整段 HTML 一次性写入会被压平并剥离样式；按顶层节点分别写入则不会出现该问题。

**使用建议**

导入前先清空编辑器正文，再执行一次注入。这是最容易暴露样式丢失的场景，建议作为常规验证步骤。

**悬停预览**

鼠标停留在组件卡片约 130 毫秒后，浮层出现在浮窗一侧，显示该组件的预设效果。预览内容固定使用组件的默认字段值渲染，不读取编辑器选区，以免被误解为实际插入结果。

浮层为 320 像素宽，高度按视口计算，上限为 `min(480, max(280, 视口高度 × 0.55))`。短组件按内容高度收起，下限 88 像素；长组件在达到上限时显示底部渐隐提示。浮层挂载在真实 `document.body` 上，并采用两层 Shadow Root 隔离，分别隔绝页面 CSS 与组件自带样式。浮层设置了 `pointer-events: none`，全程不夺取焦点，因此编辑器选区保持不变。

**点击插入**

单击卡片将组件插入编辑器当前光标位置。若正文中存在选中文字，扩展会尝试将文字填入组件的正文类字段，再用组件样式替换选区。判定规则如下：

- 字段类型为 `textarea` 时视为正文字段。
- 字段类型为 `text` 且名称或标签不属于数据、链接、图片、颜色等类别时视为正文字段。
- 纯数据、图片、分隔类组件没有正文字段，此时只按默认值插入，不改动选中文字。

填入前会对文字执行 HTML 转义，并将换行转换为 `<br>`，避免 `<`、`&` 等字符被当作标签解析。插入完成后通知条会说明是替换选区还是插入光标处，以及替换的字符数。

**键盘操作**

组件卡片可通过 Tab 键聚焦。回车或空格执行插入，Shift+回车打开参数配置。分类切换只更新标签状态，不重建标签栏，键盘焦点得以保留。搜索或切换分类后，结果区自动回到视口顶部。

### 3.3 组件参数配置

对组件卡片按住 Shift 并点击，可打开参数弹窗。弹窗根据组件字段类型生成对应控件：

| 字段类型 | 控件 |
| --- | --- |
| 多行文本 | 文本域 |
| 颜色 | 拾色器与十六进制文本框联动 |
| 数字 | 数字输入框 |
| 单行文本 | 文本框 |

无字段组件不显示表单，弹窗内直接展示预设效果并提供插入按钮。

参数预览区默认收起。修改任一字段时预览实时刷新，也可点击「预览」手动展开。弹窗底部提供取消与插入编辑器两个操作。关闭弹窗会清除待选插槽状态，避免下次点击「快捷」时填入过期的插槽索引。

选中文字中含 `<`、`>`、`&` 时会先转义再拼接 HTML，不会破坏正文结构。

### 3.5 自定义插槽

快捷排版区下方提供 3 个固定插槽，用于存放高频使用的组件。

固定方式有两种：

1. 点击组件卡片上的「快捷」按钮，组件自动填入第一个空插槽。
2. 先点击浮窗中的空插槽，再点击目标组件的「快捷」按钮，组件填入指定插槽。

插槽配置保存在浏览器本地存储中，键名为 `di_custom_toolbar`。三个插槽存满后继续固定会给出提示。点击已填充的插槽即可将对应组件插入编辑器，行为与从组件库点击卡片一致。

执行普通插入或关闭参数弹窗时，待选插槽索引会被清零，不会残留到下一次操作。

### 3.6 浮窗交互

浮窗采用固定定位，高度按 `calc(100vh - 顶部偏移 - 底部留白)` 计算，矮屏预留 16 像素，常规视口预留 32 像素，并设置 160 像素的最小高度。窗口尺寸变化时高度自动重算，不设固定上限。

按下浮窗头部并拖动可改变位置。拖到屏幕左右边缘时自动吸附为贴边状态；停在中间时保持自由定位，窗口缩放不会弹回边缘。拖动上界限制在 `视口高度 - 200` 像素，避免最小高度将底部顶出屏幕。

收起后浮窗变为约 32 像素宽、44 像素高的细把手。再次点击展开，高度恢复自适应结果。

位置条包含「排版」「插槽」「操作」「组件库」四个静态芯片。点击芯片滚动到对应分区，滚动过程中当前分区会高亮。位置条下方有一条细滚动轨，反映整条滚动流的位置。

浮窗内部只有 `.di-tb-body` 一个滚动容器。品牌头、通知条、位置条与页脚常驻可见，不随内容滚动。

### 3.7 状态检测与通知

「检测状态」按钮用于重新探测编辑器连接。状态栏显示连接结果，成功时包含编辑器版本信息，并只推送一条通知，不会同时出现「正在检测」与结果两条。

所有操作反馈统一显示在滚动区之外的通知条中。通知条位于浮窗上部，不受内容滚动影响，也不会被组件库长列表挤出可视范围。

## 技术实现说明

扩展采用 Manifest V3，内容脚本运行在隔离环境中。面板以 Shadow DOM 承载，拥有独立的 HTML 与 CSS，不与公众号页面样式互相干扰。

跨帧选区探测采用广度优先方式扫描同源 iframe，按可见面积选择最大的可编辑区域作为正文编辑器。该能力同时服务于组件插入与快捷排版。

注入链以 2026 年 11 月 8 日的备份版本为基准锁定。预处理、片段包装、帧探测与逐段写入这四个环节的行为保持稳定，自检脚本会对其中四段函数逐字比对。界面层的改动不应触及这段逻辑。

所有组件定义、插槽配置和状态数据均存储在浏览器本地，扩展不发起数据上传请求，也不需要账号登录。

## 边界与限制

- 真实公众号编辑器中的注入结果需要登录后进行实测。仓库内的自检覆盖页面结构与脚本层，不能替代编辑器内的实际验证。
- 公众号编辑器未提供注册自定义菜单项的接口。早期尝试向原生工具条追加入口会被框架重渲染清除，并改变样式作用的目标文档，因此不再重试该方案。
- 扩展只保留一种注入行为，不提供保真模式、兼容模式等开关。
- 悬停预览展示组件默认文案，不读取编辑器选区，这是刻意设计。
- 导入功能仅剥离脚本类内容，不做强清洗。若导入的网页自带全局样式，这些样式会随内容一起进入正文。

## 开发与自检

运行静态自检：

```bash
node tools/check-extension.mjs
```

通过标准为输出 `[OK] 全部关键检查通过`。检查项覆盖 5 个 JavaScript 文件的语法、66 个组件、浮窗结构、卡片交互、视口自适应算式、4.8.0 交互修复断言，以及注入链与基准版本的一致性。
